Headline findings

Coverage and access are separate dimensions

The initial catalog lookup returned 71 candidate matches, but an audit found that 14 were only related/variant results (for example, an MCP-specific toolkit or a different product returned by fuzzy search). The corrected classification is 57 exact matches + 14 related/variant results + 29 no exact match.

Access is often the practical blocker: APIs can be technically public while production access, partner OAuth, app review, customer enablement, admin approval, or commercial contracts add friction.

MCP should also be split into official/first-party versus community/third-party; the latter is not enough to claim a vendor-supported MCP integration.

Before the human correction, 33/39 (84.6%) sampled claims were directly supported as stated. After the one correction, 34/39 (87.2%) had a supported final answer; 5 remained unresolved rather than being guessed.

Concrete miss: Google Ads. The first pass treated a developer token as required. Google's current documentation says developer tokens were sunset on September 9, 2026 and are now optional/ignored by API servers; project API access and OAuth still matter.
Honest misses

What is not being claimed

  • This is not 100-app manual verification.
  • “Related catalog result” is not treated as an exact Composio toolkit.
  • “MCP mentioned” is not treated as an official vendor MCP.
  • Buildability remains provisional where access or identity is unclear.
  • Unresolved claims remain unresolved.
